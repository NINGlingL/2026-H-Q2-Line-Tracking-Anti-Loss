## 用户

你用的是什么算法

## 助手

**纯陀螺仪 Z 轴积分**。六轴 MPU6050 没有磁力计，无法获得绝对航向。

```
yaw += gyro_z × dt
```

每次循环读校准后的 Z 轴角速度，乘以实际时间间隔，累加到 yaw。

**特点：**
- 短期精度高，转动 90° 基本就是 90°
- 长期会漂移（约 0.5°/分钟），因为没有磁力计修正
- 只适合**相对角度**测量（比如转弯控制），不能当指南针用

代码里虽然函数名叫 `ComplementaryFilterUpdate`，但实际上加速度计只修正了 roll/pitch，yaw 是纯积分。

库里有 Mahony 四元数滤波，但**六轴 MPU6050 没有磁力计**，无论用什么算法，yaw 都只能是陀螺仪 Z 轴积分——加速度计只能修正 roll/pitch，无法观测绕重力轴的旋转。

## 用户

这个库可以直接用到ICM20948身上吗

## 助手

**不能直接用。**虽然都是 I2C 器件，但差别很大：

| | MPU6050 | ICM-20948 |
|------|----------|------------|
| 传感器 | 6 轴 (加速度+陀螺仪) | **9 轴** (加速度+陀螺仪+磁力计) |
| 寄存器地址 | 固定映射 | **Bank 切换** (REG_BANK_SEL=0x7F) |
| WHO_AM_I | 0x68 | 0xEA |
| 磁力计 | ❌ 无 | ✅ AK09916 (独立 I2C 地址 0x0C) |

**好消息**：ICM-20948 有磁力计，可以做真正 9 轴融合，**YAW 不会漂移**——这是 MPU6050 最大的短板。

你要换 ICM-20948 的话，需要重写驱动（寄存器地址、Bank 切换、磁力计访问）。要不要我基于这个 MPU6050 库的框架改一个 ICM-20948 版本？

## 用户

那我循迹模块需要写驱动库吗

## 助手

不需要。循迹模块本质就是几个红外对管，输出的是**数字信号**（高/低电平），直接读 GPIO 就行：

```c
// 比如 5 路循迹模块接 PB0~PB4
uint8_t sensors = DL_GPIO_readPins(GPIOB, 
    DL_GPIO_PIN_0 | DL_GPIO_PIN_1 | DL_GPIO_PIN_2 | 
    DL_GPIO_PIN_3 | DL_GPIO_PIN_4);

// sensors 每一位对应一路，1=白 0=黑
if (sensors == 0b00000) { /* 全黑，脱线 */ }
if (sensors == 0b00100) { /* 中间黑，直走 */ }
if (sensors == 0b00011) { /* 右边黑，右转 */ }
```

在 SysConfig 把对应引脚配成 **Input + Pull-up** 就行，不需要任何驱动库。你的循迹模块是几路的？
