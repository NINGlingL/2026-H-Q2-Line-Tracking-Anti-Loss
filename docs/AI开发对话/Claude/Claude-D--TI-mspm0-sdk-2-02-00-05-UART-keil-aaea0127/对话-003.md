### 修复 1: `snprintf` → `SSD1306_ShowNum`

moto 项目的代码里有一行注释：**"用 ShowNum 避免 snprintf 问题"**。这个平台的 `snprintf` 格式化数字有问题，`%lu` 会输出 `0xFFFFFFFF`。现在所有数字都用 `SSD1306_ShowNum` 显示：

```c
// 之前 (错): snprintf(buf, sizeof(buf), "RX:%lu ...", (unsigned long)g_rx_total);
// 现在 (对): SSD1306_ShowString(0, 54, "RX:");
//            SSD1306_ShowNum(0, 78, (int32_t)g_rx_count, 6);
```

### 修复 2: UART 在自检前禁用

moto 项目的 `SYSCFG_DL_UART_0_init()` 不带 RX 中断使能。但你的 SysConfig 配置了 `enabledInterrupts = ["RX"]`，所以 UART 初始化后 RX 中断已经打开了。自检期间 HC-05 发来的数据会触发中断标志残留。

```c
// 自检前禁用 UART
DL_UART_Main_disable(UART_0_INST);

// ... 1秒自检 ...

// 自检后重新配置并启用
DL_UART_Main_configBaudRate(UART_0_INST, CPUCLK_FREQ, 9600);
DL_UART_Main_setRXFIFOThreshold(...);
DL_UART_Main_enableInterrupt(...);
DL_UART_Main_enable(UART_0_INST);

// 清除残留中断标志
DL_UART_Main_clearInterruptStatus(UART_0_INST, 0xFF);
NVIC_ClearPendingIRQ(UART_0_INST_INT_IRQN);
```

现在 OLED 显示应该正常了，RX 从 0 开始计数。

三个关键修复：

### 1. UART_1 (PA10/PA11) 不用中断 — 杜绝 ISR 风暴

PA11 浮空 → RX 引脚电平漂移 → UART 把它当成不断收到的数据 → 中断疯狂触发 → CPU 被 ISR 占满 → 主循环无法处理 HC-05 指令。

**修复**：UART_1 改为纯轮询，不使能 NVIC 中断：
```c
// UART_1 只配波特率+使能，不开中断
DL_UART_Main_configBaudRate(UART_1_INST, CPUCLK_FREQ, 9600);
DL_UART_Main_enable(UART_1_INST);
// 没有 NVIC_EnableIRQ(UART_1_INST_INT_IRQN)
