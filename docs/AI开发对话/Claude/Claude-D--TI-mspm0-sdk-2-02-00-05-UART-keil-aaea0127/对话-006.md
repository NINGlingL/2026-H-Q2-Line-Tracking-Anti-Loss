## 助手

好，纯分析。

**症状特征**：第一条指令 100% 正确 → 后续乱。这是典型的缓冲区指针/数据完整性问题，而不是硬件故障（硬件坏的话第一条也错）。

我的分析按优先级排列：

---

### 1. 最大嫌疑：蓝牙终端 App 发送了不可见字符

大部分蓝牙串口 App (包括手机上的) 默认会在每个字符后追加 `\r\n`。你发 `F`，实际 HC-05 收到的是 `F\r\n` 三个字节。主循环逐个处理：

```
'F'  → Forward  ✓
'\r' → default → snprintf(g_last, "?:\r")  不改变电机
'\n' → default → snprintf(g_last, "?:\n")  不改变电机
```

这个还好，但如果 App 不是加 `\r\n` 而是加了别的控制字符，或者在连接/断开时发了模块状态信息，就会乱。更关键的是**环形缓冲区没有字符过滤**——所有字节都吞进去，包括不可见字符。

### 2. OLED 刷新期间 ISR 可能丢数据

```
main:                           ISR:
  UartBT_Read(&c) -- 读g_wr
                                ← 中断! 修改 g_wr
  *c = g_ring[g_rd]             
                                ← 又中断! 又改 g_wr
  g_rd++                        
  Cmd_Exec(c)                   
  UartBT_Read(&c) -- 再读g_wr   
```

`OLED_Show()` 里 `SSD1306_Update()` 是一次完整的 I2C 传输(128×8=1024字节)，期间 ISR 可能触发多次往缓冲写数据。等 OLED 刷新完，主循环 `while(UartBT_Read)` 一口气把所有积压字节全处理了——如果中间夹杂了垃圾字节，电机就会收到乱指令。

### 3. 数字键 '1'-'9' 强制切方向为 Forward

```c
case '1': Moto_Forward(10);  // 不管当前方向，直接变前进
```

如果你正后退时按 `5` 想减速，车会**突然变成前进 50%**，感觉就像指令乱了。

---

### 建议修复方案

| 优先级 | 措施 |
|:-:|------|
| P0 | `UartBT_Read` 里过滤不可见字符，只放 `FBLR S+-0123456789` 进缓冲区 |
| P1 | 数字键只调速不切方向（方向为 S 时才切 Forward） |
| P2 | 主循环用 `UartBT_GetCommand` 逐行处理，而不是逐字节 |
