## 助手

|----------|-------------|
| **STM32CubeIDE 命令行** | 编译固件（headless build） |
| **OpenOCD + ST-Link** | 烧录 Flash、读写内存/寄存器、设置断点 |
| **串口驱动** | 与单片机收发数据 |

这些原本需要你在终端手动敲命令，stm32-mcp 把它们包装成了 MCP 工具函数。

---

## 第三层：实际工作流

以"修改 LED 闪烁频率"为例：

```
1. 你说："帮我把 LED 闪烁频率从 200ms 改成 500ms"

2. Claude Code 理解意图：
   → 需要修改 main.c 中的 delay 值
   → 需要重新编译
   → 需要烧录到芯片

3. Claude Code 执行：
   a) 用 Edit 工具修改 main.c（普通文件编辑）
   b) 调用 MCP: build_firmware()
        └→ stm32-mcp 执行：STM32CubeIDE --headless --build
        └→ 返回：编译成功 / 编译错误
   c) 调用 MCP: flash_firmware()
        └→ stm32-mcp 执行：openocd -f stlink.cfg -c "program xxx.elf verify reset"
        └→ 返回：烧录成功
   d) 调用 MCP: serial_read()
        └→ 读取串口输出，验证 LED 是否按新频率闪烁

4. 如果有编译错误：
   Claude Code 读到错误信息 → 自动修改代码 → 重新编译 → 直到通过
```

## 总结

这个项目的本质是**把 STM32 开发工具链包装成 AI 可调用的函数**，让 Claude Code 从"只能写代码"变成"能写、能编译、能烧录、能调试"。

和之前提到的 skill 的区别：

| | Skill | MCP Server |
|------|-------|------------|
| 本质 | 给 AI 的**操作指南**（文本） | 给 AI 的**外部工具**（程序） |
| 能做什么 | 影响 AI 怎么思考和写代码 | 让 AI 直接操作硬件和工具链 |
| 安装方式 | 放文件夹 | 需要启动一个后台进程 |
| 依赖 | 无 | 需要装 STM32CubeIDE、OpenOCD 等 |

**Skill 教 AI 怎么想，MCP 让 AI 能做。两者配合才是完整的。**

要不要试装这个？前提是你电脑上得先装好 STM32CubeIDE 和 ST-Link 驱动。

## TI MSP M0 相关 MCP Server

**一个都没有。**

搜遍全网，没有任何针对 TI MSPM0 系列的 MCP Server。原因也不复杂：

1. **OpenOCD 对 MSPM0 支持有限** — 只在 Zephyr RTOS 环境下有初步支持，不像 STM32 那样成熟
2. **probe-rs 不支持 MSPM0** — 这个最主流的嵌入式调试框架目前没适配 TI 的芯片
3. **MSPM0 生态相对封闭** — 调试主要靠 TI 自家的 XDS110 调试器和 CCS IDE，开源工具链覆盖不足
4. **社区关注度低** — 用 Claude Code 做 MSPM0 开发的人极少，没人做这个轮子
