## 一、现状核对（我读到的事实）

| 项目 | 状态 |
|------|------|
| 题目 | H题「车载平衡滚球运动控制系统」：循线小车 + 摆杆控球。任务2（一圈≤20s）你已完成 |
| 视觉端 | MaixCam Pro 用 YOLO26 检测钢球，标定轴 0~25cm，**每 50ms 发一次 `{位置cm:.2f}\n`**（纯浮点+换行，无帧头），丢球时不发 |
| vision/keil | 已有 UART0（PA10/PA11，115200）环形缓冲 + I2C0 OLED 显示，可直接迁移 |
| TMC2208/keil | **是空白工程**，只有空 main 循环，无电机代码 |
| 电机 | 28HS30-0604A-013（NEMA 11 / 28mm，丝杆型待确认） |

有一个**关键发现**要先提醒你：vision/keil 里那份代码其实只是"把收到的字符显示到 OLED"，**并没有真正解析球坐标协议**；而且它写的是 `$BALL,...*` 帧协议，但 Python 实际发的是 `12.34\n` 这种裸浮点。所以迁移时解析器要按**行缓冲 + atof**来写，不能直接照抄那个工程的主程序，只迁移它的 UART 配置和环形缓冲即可。

## 二、对系统的理解（确认一致）

摆杆左端铰链固定（高 h≥5cm），右端由步进电机+丝杆**升降**。抬升右端 → 杆向铰链侧倾斜 → 球滚向左侧；下降右端 → 球滚向右侧。视觉回传球坐标 → MCU 跑 PID → 给步进发位置指令。这就是一个典型的"球-板"平衡的简化版（一维线性版本）。
