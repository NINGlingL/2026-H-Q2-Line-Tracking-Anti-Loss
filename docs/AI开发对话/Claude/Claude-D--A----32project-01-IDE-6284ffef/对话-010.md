### 🥈 方案二：pyOCD Commander（命令行快速看寄存器）

```bash
pip install pyocd
pyocd pack install MSPM0G3507
pyocd cmd --pack=TexasInstruments.MSPM0G_DFP.1.1.0.pack -t mspm0g3507
```

进去之后直接：
```
> read32 0x40000000    # 读 GPIO 寄存器
> reg                  # 看 CPU 寄存器
> status               # 查看当前连接状态
```

**优点**：500KB 安装，秒开，不依赖任何 IDE。

### 🥉 方案三：Compact Debugger（CHAOS）

https://chaos-neonx.github.io/

- 纯 C 写的独立 exe，**~500KB**
- 原生 CMSIS-DAP 支持
- **动态刷新的 WATCH + MEMORY 窗口**（TUI 界面）
- 不需要任何 IDE，双击打开就能用

### 🏅 方案四：最土但最快 — UART printf

**MSPM0G3507 是 Cortex-M0+，没有 SWO/ITM，用不了 Keil 的 Debug (printf) Viewer。** 所以最靠谱的是 **HC-05 蓝牙当串口打印**，你已经有了：

```c
#include <stdio.h>

// 重定向 printf → UART
int fputc(int ch, FILE *f) {
    DL_UART_Main_transmitDataBlocking(UART_0_INST, (uint8_t)ch);
    return ch;
}
```

然后代码里四处打 `printf("Motor: %c, L=%d R=%d\r\n", dir, L, R);`，手机蓝牙串口 APP 直接看。

### 总结

| 方案 | 难度 | 能看什么 | 适合场景 |
|------|------|---------|---------|
| **VS Code + TI Debug** | ⭐⭐ | 所有寄存器、变量、断点 | 日常开发调试 |
| **pyOCD cmd** | ⭐ | 内存、寄存器 | 快速排查硬件 |
| **CHAOS** | ⭐ | WATCH+MEMORY | 轻量极简 |
| **UART printf** | ⭐ | 你想打印的任何东西 | 运行时调试 |

> **建议**：方案一 + 方案四一起用。VS Code 里断点看寄存器状态，手机上蓝牙看实时运行输出。两个配合，基本不会再有"不知道哪崩了"的情况。

## 能让我一键烧录调试的工具

### 🥇 embedded-debugger-mcp（最佳匹配）

**GitHub**: https://github.com/adancurusul/embedded-debugger-mcp

这是目前唯一**原生支持 CMSIS-DAP + Cortex-M0+ + Claude Code 插件**的 MCP：

- probe-rs 后端 → 原生 CMSIS-DAP 支持，不用绕 OpenOCD
- 支持 **MSPM0 系列**（probe-rs v0.28 已加入 TI MSPM0）
- 22 个工具：烧录 ELF/HEX/BIN、读写寄存器/内存、断点、RTT、复位
- 自带 `claude` 技能安装命令

安装后我就能做的事情：

| 我现在能做到的 | 具体效果 |
|-------------|---------|
| **一键烧录** | 我写代码 → 编译 → 自动烧录到板子，全程不用你动手 |
| **读寄存器** | 烧完出 bug，我直接读 GPIO/I2C/UART 寄存器看哪里不对 |
| **断点调试** | 设断点、单步执行、读变量值 |
| **读内存** | 直接 dump 任意地址内容 |
| **RTT 日志** | 实时读 MCU printf 输出 |

### 🥈 备选：OpenOCD MCP Server

**GitHub**: https://github.com/royforlinux/openocd-mcu-mcp

如果你的 DAP 调试器 probe-rs 识别不了，用这个走 OpenOCD 后端：

```
pip install openocd-mcu-mcp
```
