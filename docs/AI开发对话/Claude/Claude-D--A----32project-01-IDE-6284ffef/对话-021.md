## 你下的这个 skill 是什么

`embedded-hardware-safety-review` = **硬件安全审查**，不是代码风格审查。

它做的是：

```
AI 生成代码 → 60项物理安全检查 → 通过才允许输出

例如:
  ❌ PWM=100%  → 🔴 P0 铁律: 必须限幅到 85%
  ❌ 无看门狗   → 🔴 P0 铁律: I2C卡死→小车全速冲出去
  ❌ 无电池ADC  → 🔴 P0 铁律: 低压→MCU复位→GPIO乱跳
```

**专门防止你刚才那种烧板子的事故。**

---

## 代码审查有别的

Claude Code 自带 **`/code-review`** 技能（检查 bugs、简化、性能），和这个是两码事：

| | `/code-review` | `embedded-hardware-safety-review` |
|------|------|------|
| 查什么 | 逻辑 bug、死代码、内存泄漏 | **PWM限幅、看门狗、电池ADC、急停** |
| 防什么 | 程序跑飞、结果错误 | **烧芯片、炸驱动、小车失控** |
| 适用 | 所有代码 | 嵌入式固件（电机/IMU/PID） |

---

**总结：你下的这个 skill 没有"代码审查"功能，它是"别把板子烧了"审查器。** 两个配合使用最佳——代码审查保逻辑正确，硬件安全审查保物理安全。

3507的PA17 PA18哪一个是调试串口？

## 助手

MSPM0G3507 上没有专门的"调试串口"。

| 引脚 | 功能 | 备注 |
|------|------|------|
| **PA10** | UART0 TX | 天猛星板子通常用这个做串口打印 |
| **PA11** | UART0 RX | |
| PA17 | UART1 TX（复用） | 普通 GPIO，可配成串口但不是默认 |
| PA18 | UART1 RX（复用） | 同上 |

---

**你 UART 项目的配置**：

| 串口 | 引脚 | 用途 |
|------|------|------|
| UART_0 (UART2) | PA21=TX, PA22=RX | **HC-05 蓝牙** |
| UART_1 (UART0) | PA10=TX, PA11=RX | **Debug 串口**（你之前配的） |

---

**如果你想要调试打印**，用 **PA10/PA11**（UART0），接一个 USB 转 TTL 模块，电脑上打开串口助手就能看 `printf` 输出。

PA17/PA18 没有任何硬件级调试功能，它们只是普通的 UART1 复用脚。
