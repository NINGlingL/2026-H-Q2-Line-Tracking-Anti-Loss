## 关键设计决策

### 1. 硬件 vs 软件编码器

| | 编码器 1 (左轮) | 编码器 2 (右轮) |
|---|---|---|
| 实现方式 | 🔧 **TIMG6 硬件 QEI** | 📝 **GPIOB 中断 + 软件** |
| 引脚 | PA5 + PA6 | PB0 + PB1 |
| 计数精度 | 4x 倍频，硬件自动计数 | 4x 倍频，ISR 软件计数 |
| CPU 开销 | 零 (硬件) | 低速时可忽略，高速需关注 |
| 中断 | 可选 (溢出/方向变化中断) | GPIOB 双边沿中断 |

**为什么 G3507 只有一个硬件编码器？** 你的判断是对的。G3507 有多个 TIMG，但要同时跑两个硬件 QEI 且不与其他外设冲突比较困难。TIMG6 的 CCP0/CCP1 恰好映射在 PA5/PA6 这两个"空闲"引脚上，非常适合做硬件编码器。另一个用软件实现，PB0/PB1 共享 GPIOB 的单个中断向量。

### 2. OLED + ICM20948 共用 I2C0

| 设备 | I2C 地址 | 速率 |
|------|---------|------|
| SSD1306 OLED | 0x3C | 400kHz |
| ICM20948 IMU | 0x68 (AD0=GND) | 400kHz |

两个地址不冲突，一条 I2C 总线搞定。比用两个 I2C 省 2 个引脚。

### 3. TB6612 STBY 引脚 (PB4)

原来 `moto.h` 里 STBY 硬连线到 3.3V（无法软件控制），现在通过 PB4 控制：
- 急停/故障时拉低 STBY → 所有电机立即断电
- 不增加额外引脚开销

### 4. 5 路循迹全在 GPIOB

PB5-PB9 五个引脚都在 GPIOB 上，可以一次读 `DL_GPIO_readPins(GPIOB, 0x03E0)` 拿到全部 5 路状态，效率高。
