   说明模块确实在发数字帧，但传感器判断全是白底。那就不是串口问题了，重点检查：
   - 探头高度
   - 黑线宽度/颜色

## 助手

你这个现象很关键：

- `RX` 增长：串口接收没问题。
- `T` 一会儿显示 `- / 1 / 0 / D`：说明收到的 `$...#` 帧里，第二个字符不稳定，有些是我们自己发出的命令回显/噪声/非标准帧。
- `D` 没稳定增长、`bad` 慢慢涨：说明确实偶尔收到了 `$D...#`，但格式和 PDF 示例可能不完全一样，或者帧被切碎/夹杂了别的字符，导致原解析没认出来。

我又改了一版解析器，做了兼容：

现在不仅支持 PDF 标准格式：

```text
$D,x1:0,x2:1,x3:0,x4:0,x5:0,x6:0,x7:0,x8:0#
```

也兼容类似这种简化格式：

```text
$D,0,1,1,1,1,1,1,1#
$D,01111111#
```

编译已通过：

```text

```

你重新烧录这版再看：

- 如果 `D` 开始增长，且压黑线后 `RAW` 会变，就说明就是帧格式兼容问题，已经解决。
- 如果 `D` 仍然不增长，但 `T` 经常变成 `D`，那下一步我会把“最近收到的一整帧”转成 OLED 可显示的简写，例如显示前 16 个字符，这样能直接看到模块实际发的是什么格式。
- 如果 `D` 不增长，`T` 主要是 `0/1`，那大概率是模块把我们发的 `$0,0,1#` 命令也回显回来了，或者 TX/RX 线上有干扰/接线回环，需要进一步确认模块 TX/RX 接法。
