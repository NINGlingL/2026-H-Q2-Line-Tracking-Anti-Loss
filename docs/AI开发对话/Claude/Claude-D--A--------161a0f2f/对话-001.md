## 助手

**不是通用的**。当前驱动与 TI MSPM0 平台强耦合，换一个平台（比如 STM32、GD32、ESP32）完全无法直接使用。以下是具体问题：

### 1. I2C 层硬编码了 TI MSP 的 API

`mpu6050.c` 中的所有 I2C 读写都直接调用了 TI DriverLib：

```c
// 每个读写函数里都是这些 MSP 专属调用
DL_I2C_getControllerStatus(MPU6050_INST)
DL_I2C_fillControllerTXFIFO(MPU6050_INST, ...)
DL_I2C_startControllerTransfer(MPU6050_INST, ...)
DL_I2C_receiveControllerData(MPU6050_INST)
```

`MPU6050_INST` 这个宏是在 `ti_msp_dl_config.h` 里定义的，换平台根本不存在。

### 2. 时间函数硬编码

```c
Board_Millis()   // 来自 board.h，平台相关
delay_ms()       // 来自 board.h，平台相关
```

### 3. 引入了应用层依赖

```c
#include "PID.h"    // 角度 PID 转弯控制用到
#include "line.h"   // 巡线模块，但其实没用到（冗余引入）
```

`MPU6050_TurnAngle()` 还直接调用了 `Car_Stop()`、`Car_SetMotors()`，这些是你们小车项目的函数，跟 MPU6050 传感器本身没关系。

### 4. 头文件锁死了平台

```c
#include "ti_msp_dl_config.h"  // mpu6050.h 第一行就是 MSP 专属头文件
```

| 问题 | 方案 |
|------|------|
| I2C 读写 | 抽象为 HAL 回调函数指针 (`i2c_write` / `i2c_read`) |
| 延时/计时 | 抽象为 `delay_ms` / `millis` 回调 |
| AnglePID / TurnAngle | 拆分到 `mpu6050_app.c`，跟传感器驱动解耦 |
| PID / Car 依赖 | 应用层自己管理，不污染传感器驱动 |

### 缺失的头文件

```
mpu6050.h → #include "ti_msp_dl_config.h"   ← SysConfig 生成的，不在这个目录
mpu6050.c → #include "board.h"              ← 不在这个目录（Board_Millis、delay_ms）
mpu6050.c → #include "PID.h"                ← 不在这个目录（PID_Init、PID_Calculate）
mpu6050.c → #include "line.h"               ← 不在这个目录（而且根本没用到）
```

### 缺失的宏和函数

| 符号 | 来源 | 用途 |
|------|------|------|
| `MPU6050_INST` | `ti_msp_dl_config.h` | I2C 外设实例号 |
| `Board_Millis()` | `board.h` | 系统毫秒计时 |
| `delay_ms()` | `board.h` | 毫秒延时 |
| `PID_t / PID_Init / PID_Calculate / ...` | `PID.h` | 角度 PID 控制 |
| `Car_Stop() / Car_SetMotors()` | 小车工程 | 电机控制 |

### 结论

这是从你的小车项目里**直接复制粘贴**出来的中间产物——只做了文件拆分，没有做解耦。你要用的话，得把它放回原来那个完整工程里，让那些 `#include` 都能找到对应的文件才行。
