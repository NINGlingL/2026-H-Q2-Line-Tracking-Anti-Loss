## 助手

**HAL = Hardware Abstraction Layer（硬件抽象层）**

这个 MPU6050 驱动 (`mpu6050.c/h`) 是一个**通用驱动**，它不依赖任何特定 MCU。所有跟硬件打交道的操作——I2C 读写、延时、计时——都是通过一个叫 `mpu6050_hal_t` 的结构体来完成的，里面存的是**函数指针**：

```c
typedef struct {
    void     (*i2c_write)(...);       // I2C 写一个寄存器
    uint8_t  (*i2c_read)(...);        // I2C 读一个寄存器
    void     (*i2c_read_burst)(...);  // I2C 连续读多个寄存器
    void     (*delay_ms)(...);        // 毫秒延时
    uint32_t (*millis)(void);         // 获取系统毫秒时间戳
} mpu6050_hal_t;
```

**打个比方**：驱动就像一个万能遥控器，HAL 就是遥控器底部的电池仓——不管你是南孚还是松下（MSPM0 还是 STM32），只要装上对应的电池（实现这 5 个函数），遥控器就能工作。

所以针对 MSPM0G3507，我需要用 DriverLib 来实现这 5 个函数：

| HAL 函数 | MSPM0 实现方式 |
|:-:|:-:|
| `i2c_write` | `DL_I2C_fillControllerTXFIFO` + `DL_I2C_startControllerTransfer` (I2C_1) |
| `i2c_read` | I2C 先写寄存器地址，再读 1 字节 |
| `i2c_read_burst` | I2C 先写寄存器地址，再连续读 N 字节 |
| `delay_ms` | `delay_cycles(CPUCLK_FREQ / 1000 * ms)` |
| `millis` | 返回 `g_tick_ms`（已有的 SysTick 1ms 计数） |

准备好接线后告诉我，我就把这层 HAL 实现写了，然后在 `empty.c` 里加上 MPU6050 初始化和 OLED 显示姿态角。
