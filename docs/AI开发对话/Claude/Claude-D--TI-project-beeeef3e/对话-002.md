## 助手

这个问题常见于 CCS 没有识别到 MSPM0 SDK。让我检查一下你的 CCS 配置。

## 助手

找到原因了。设备文件 `MSPM0G3507.xml` 和 SDK 都在，但 CCS 的 **产品发现（Product Discovery）** 没有注册 MSPM0 SDK，所以新建工程向导不认识这个芯片。

## 解决方案

### 方案一：用导入代替新建（推荐，1 分钟搞定）

MSPM0 开发的标准做法是**从示例工程导入，而不是从零新建**。SDK 里有现成的空工程模板：

1. CCS 菜单：**Project → Import CCS Projects**
2. 搜索路径选：
   ```
   D:\TI\mspm0_sdk_2_11_00_07\examples\nortos\LP_MSPM0G3507\driverlib\empty
   ```
3. 勾选 `empty`，点击 **Finish**
4. 右键这个工程 → **Rename** 改成你的项目名
5. 在此基础上改代码即可

这个空工程已经帮你配好了芯片型号、编译器、链接脚本、SysConfig，不需要从零填参数。

### 方案二：修复产品发现（让新建向导识别芯片）

1. CCS 菜单：**Window → Preferences**
2. 左侧树形菜单：**Code Composer Studio → Products**
3. 点击 **Refresh** 按钮，让它扫描已安装的产品
4. 如果 MSPM0 SDK 没出现，点 **Add**，手动指向 `D:\TI\mspm0_sdk_2_11_00_07`
5. 点击 **Apply and Close**
6. 重启 CCS，再次新建工程时就能搜到 `MSPM0G3507` 了

> [!note] 为什么推荐方案一
> 即使方案二修好了，新建工程后还得手动配 SDK 路径、SysConfig、链接脚本等一堆东西。导入 `empty` 模板一步到位，这些配置都已就绪，这是 TI 官方推荐的 MSPM0 开发流程。

## 用户

我在选择模型时遇到了有BOARD和DEVICE两个选项但是第一个选项是官方板子第二个只有单纯的3507

## 助手

选 **DEVICE**（`MSPM0G3507`）。

你的国产核心板和 TI 官方 LaunchPad 的区别就在于这里：

| 选项 | 含义 | 适用场景 |
|------|------|----------|
| **BOARD** → `LP_MSPM0G3507` | 官方 LaunchPad，引脚、外设都已锁定 | TI 官方板子 |
| **DEVICE** → `MSPM0G3507` | 纯芯片，引脚你自己在 SysConfig 里配 | **你的国产核心板** ✅ |

选 DEVICE 后，SysConfig 里的引脚配置是空白的，你可以根据自己核心板的实际走线自由分配 GPIO 功能——这才是你需要的。

## 用户

Device-id 'MSPM0G3507' is not recognized可是我选择这个以后选择LED模板报错啊

## 助手

这不是你操作的问题，是同一个根因——CCS 没有把 MSPM0 SDK 注册到自己的产品列表里。你选 DEVICE 后 CCS 要去 SDK 里找对应的驱动和 SysConfig 数据，找不到就报错。

不纠缠这个新建向导了，直接用导入方式绕过去：

**一步到位：**

1. CCS 菜单 → **Project → Import CCS Projects**
2. **Search directory** 填：
   ```
   D:\TI\mspm0_sdk_2_11_00_07\examples\nortos\LP_MSPM0G3507\driverlib\gpio_toggle_output
   ```
3. 勾选 `gpio_toggle_output`，点 **Finish**
4. 工程导入后，双击 `.syscfg` 文件，把 Board 从 `LP_MSPM0G3507` 改成 `MSPM0G3507`（None/Device 模式），然后按你的核心板重新配 LED 引脚
5. 编译 → 下载

这个流程和"新建工程"最终一模一样，但跳过 CCS 新建向导那个有 bug 的环节。你试一下？

> 如果你确实想修好新建向导以备后用，我们也可以去 `Window → Preferences → Code Composer Studio → Products` 手动注册 SDK，但那个要重启 CCS，不如导入快。
