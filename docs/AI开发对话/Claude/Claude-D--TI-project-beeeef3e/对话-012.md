```

```

## 用户

那板子上那个C口是拿来干什么的

## 助手

供电 + 串口。

核心板上的 USB-C 口通常连着 **CH340** 或 **CP2102** 这类 USB 转串口芯片。它的功能是：

| 功能 | 能 / 不能 |
|------|-----------|
| 给核心板供电（5V → 3.3V） | ✅ 能 |
| 电脑串口通信（printf 调试信息） | ✅ 能 |
| 下载/调试程序（SWD 协议） | ❌ 不能 |

你核心板上 USB-C 口旁边一般会有一颗小芯片，丝印大概率是 **CH340C**、**CH340K**、**CP2102** 之类的——那就是串口芯片。

**所以 DAP-Link 还是得等。** 但 C 口不是白给的——等你程序跑起来，用它就可以在电脑上用串口助手看 `printf` 打出的调试信息了。

## 用户

不能使用串口烧录？

## 助手

可以。MSPM0 芯片内置了 **BSL（Bootloader）**，支持通过串口烧录。

芯片出厂空白或 Flash 被擦除时，上电会自动进 BSL 模式等串口发固件。你的 USB-C 口连着 CH340，刚好就是串口。

让我找一下你 SDK 里有没有现成的烧录工具。

## 助手

## 助手

SDK 里有现成的串口烧录工具。梳理一下：

**思考：**

1. MSPM0 芯片内置 ROM Bootloader（BSL），空白芯片上电自动进 BSL 模式
2. BSL 支持 UART 协议——刚好和你板子上的 CH340（USB 转串口）匹配
3. 流程：编译出固件 → USB-C 线插电脑 → COM 口出现 → BSL 工具通过串口把固件发过去

**关键问题**：你核心板上 CH340 串口芯片的 TX/RX 连的是芯片的哪两个引脚？BSL 默认用 **PA8 (TX) / PA9 (RX)** 或者特定的 UART 引脚。如果厂家把 CH340 连到了别的引脚上，BSL 就收不到数据，烧录失败。
