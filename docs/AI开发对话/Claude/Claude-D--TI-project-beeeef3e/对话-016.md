## 助手

标签写的是"预留 SWD 调试接口"但引脚标的却是 PA10/PA11？这矛盾了——PA10/PA11 是 UART 串口脚，不是 SWD 脚（SWD 固定是 PA19/PA20）。

有两种可能：

1. **丝印错了**——实际引出的是 PA19/PA20，标成了 PA10/PA11
2. **丝印没错**——这就是串口，厂家把"串口调试"误写成了"SWD 调试"

别猜了，试一下就知道。

**用万用表蜂鸣档**（如果没有万用表就跳过）：一根表笔点芯片的第 10 脚（PA0），另一根分别点那排针的四个脚，看看哪个导通。导通的那个就是 PA0，其他同理可以推出到底引出的是哪些引脚。

或者更简单——**直接拍张核心板正反面清晰照片**，我帮你看。芯片丝印和排针走线一般肉眼能看出来。

## 关键信息

| 你的板子 | 详情 |

你看到的那排 GND/PA10/PA11/3.3 是**串口**，不是 SWD。SWD 接口在板子上**另一处**，但出厂没焊排针。

## 两个选择

### 选择一：焊 SWD（一劳永逸）

在板上找到 **SWD 焊盘**（5 个孔：GND、SWCLK、SWDIO、3V3、RST），有烙铁的话焊上排针，DAP-Link 直接插。

### 选择二：先试 BSL 串口 + 按键触发（不焊接）

板上有复位键和用户按键。试试这个组合触发 BSL：

1. 按住 **用户按键 1**（可能是 PA18，BSL 触发脚）
2. 按一下 **复位键**，松开
3. 再松开用户按键 1
4. 立刻运行：
   ```bash
   python D:\TI_project\bsl_flash.py D:\TI_project\empty_driverlib_src\Debug\firmware.hex COM8
   ```

如果两个用户按键都不行，换另一个按键重复上面的操作。**注意第 3→4 步要快。**

## 助手

🎉 **烧录成功！BSL 串口烧录搞定！**

灯暗的原因：GPIO 驱动强度默认是"弱"，电流不够。去 SysConfig 里调一下：

1. CCS 里双击 `empty.syscfg`
2. 点左边 **GPIO_GRP_0** → 点 **PIN_0**
3. 右侧面板里找 **Drive Strength**（驱动强度）
4. 从默认的 **Low** 改成 **High**
5. 保存（Ctrl+S）→ 重新编译 → 重新生成 hex → 重新 UniFlash 烧录

灯会亮很多。如果还是暗，那就是板子上 LED 串的限流电阻太大了，硬件问题，不影响使用。
