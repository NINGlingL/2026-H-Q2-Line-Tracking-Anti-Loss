## 助手

好，直接跟你说。

MPU6050 的问题在于它是 **6 轴**（3 加速度 + 3 陀螺仪），**没有磁力计**。这意味着：

- **Yaw（航向角）会不断漂移**，每秒可能漂 0.5~2°，几分钟后方向就完全不准了
- 对于 2025 E 题，小车转圈时靠 yaw 来判断方向，漂了就打不准靶心了
- 对于 2024 H 题，无循迹线直线行驶全靠 yaw 保持方向，漂了就走歪了
- MPU6050 的 DMP（硬件姿态解算）在 MSPM0 上还不好用，得自己写 Mahony 滤波

**更合适的方案**：

| 题目 | 推荐 IMU | 原因 |
|------|---------|------|
| 2025 E 题 | **ICM-20948**（9轴）或 **WT901**（串口直出欧拉角） | 需要航向无漂移才能瞄准 |
| 2024 H 题 | **HWT101 / WT901** | 串口直接读角度，代码量最少 |
| 2023 E 题 | 两个独立 **ICM-20948** | 两云台各一个，SPI 更快 |
| 2023 G 题 | 无人机 **ICM-42688-P**，地面车 **HWT101** | 前者噪声低适合飞控，后者省事 |

**简单选型逻辑**：
- 如果你不想写姿态解算代码 → **WT901 / HWT101**（串口，50 块钱，直接读出 roll/pitch/yaw）
- 如果你要高性能 + 自己写融合 → **ICM-20948**（SPI，9 轴，TDK 的，噪声比 MPU6050 低一个数量级）

MPU6050 不是说不能用，而是用了你得多花很多时间调 yaw 漂移补偿，电赛 4 天 3 夜经不起这样消耗。你现在的板子已经有 MPU6050 了对吧？那是用来学驱动的，比赛时建议直接上 9 轴的。

### 自己写姿态解算（用 MPU6050、ICM-20948）

你拿到的是**原始数据**——加速度的 3 个分量、陀螺仪的 3 个角速度。全是每秒几百个的 16 位整数。

你得自己写代码把它们融合成 roll/pitch/yaw。核心是互补滤波或 Mahony 算法：

```c
// 你要写的东西大概长这样
float q0=1, q1=0, q2=0, q3=0;          // 四元数
float exInt=0, eyInt=0, ezInt=0;        // 积分误差

void MahonyUpdate(float ax, float ay, float az,  // 加速度
                  float gx, float gy, float gz,  // 陀螺仪
                  float dt) {
    // 1. 归一化加速度
    // 2. 计算重力方向误差（叉积）
    // 3. PI 修正陀螺仪
    // 4. 四元数积分
    // 5. 归一化
    // 6. 转欧拉角
}
```

整个过程大约 150 行代码 + 大量调参（Kp、Ki、截止频率...）。

**要处理的问题**：
- 加速度有重力分量和运动加速度，怎么分离？
- 陀螺仪有零偏，静止也在漂，怎么校准？
- 6 轴没有磁力计，yaw 只能靠陀螺仪积分，每秒钟漂 1~2°，1 分钟就偏了几十度
- 电机振动传导到 IMU，数据全是噪声

**工作量**：写代码 2~3 小时 + 调参 3~5 小时 = **大半天没了**。

---

### 用自带解算的模块（WT901、HWT101）

模块里有个小单片机，上面的事它**全替你做了**。你只需要：

```c
// 发一条 UART 读指令，它直接回角度
// WT901 每秒自动发 100 帧数据，帧格式：
// 0x55 0x53 RollL RollH PitchL PitchH YawL YawH ... 
float roll  = (buf[3]<<8 | buf[2]) / 32768.0 * 180.0;
float pitch = (buf[5]<<8 | buf[4]) / 32768.0 * 180.0;
float yaw   = (buf[7]<<8 | buf[6]) / 32768.0 * 180.0;
// 完了，直接用
```

**代码量**：30 行。

**它内部做了**：
- 9 轴融合（加速度+陀螺仪+磁力计），yaw 不漂
- 自动校准零偏
- 低通滤波去噪
- 200Hz 稳定输出
