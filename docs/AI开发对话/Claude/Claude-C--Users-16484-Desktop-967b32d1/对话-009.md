## Skill 本质上是什么

Skill 就是一个**给你（Claude Code）写的操作手册**。

它是一份 Markdown 文件（`SKILL.md`），里面写了三件事：

1. **什么时候该用我**（触发条件描述）
2. **你应该怎么想、怎么做**（详细步骤指引）
3. **有什么参考资料**（可以附带附件）

类比：

| 类比 | 对应 |
|------|------|
| 新员工入职培训手册 | Skill |
| 老员工凭经验做事 | 没有 Skill 的 Claude |
| 看完手册后的新员工 | 加载了 Skill 的 Claude |

你装了 skill 之后，Claude Code 并不会"变聪明"，只是**多了一本参考手册**。当你的提问匹配到这本手册的适用范围时，它就会按照手册的指引来思考和执行。

---

## 什么情况下需要 Skill

### 不需要 Skill 的情况

如果你只是问一些通用问题，比如"帮我写个冒泡排序"、"这段代码什么意思"——不需要 skill，Claude 训练数据里就有。

### 需要 Skill 的情况

| 场景 | 为什么需要 |
|------|-----------|
| **重复性工作流程** | 比如每次 Code Review 都要检查同样几类问题 → `/code-review` 封装了完整的审查流程 |
| **专业领域知识** | 比如 MISRA-C 规则检查，Claude 不可能记住全部 100+ 条规则 → skill 把规则写进附件 |
| **多步骤操作** | 比如"搜资料→验证→写报告"，需要固定流程 → `/deep-research` 封装了搜索→核实→合成的步骤 |
| **团队规范** | 比如你们团队有特定的命名规范、注释格式 → skill 把这些规范写进去，每次写代码都遵守 |
| **需要约束输出格式** | 比如每次生成的代码必须符合 MISRA-C 2012 → skill 里写清楚规则 |

## Skill vs MCP 的区别

这是最容易混淆的地方：

| | Skill | MCP Server |
|------|------|------------|
| 是什么 | 一份**文档**（文本指引） | 一个**程序**（外部工具） |
| 怎么工作 | 加载到我的上下文中，影响我的思考和输出 | 我通过协议调用它，它执行实际操作 |
| 能做什么 | 改变我**怎么想**、**怎么写代码** | 改变我**能操作什么**（编译、烧录、读内存） |
| 举例 | "写代码时检查 MISRA 规则" | "把代码烧录到 STM32" |
| 物理存在 | 一个 `SKILL.md` 文件 | 一个后台运行的进程 |

**Skill 教我怎么写代码，MCP 让我能编译和烧录代码。两者互补，不是替代关系。**

## 以你现在的配置为例

你装了 **stm32-mcp（MCP）** + **find-skills（Skill）**：

- `stm32-mcp`：我能帮你**编译、烧录、读写内存、串口通信**
- `find-skills`：我能帮你**搜索和安装其他 skill**

你已经有了"手"（MCP），现在差的是"脑子里的知识"（Skill）——比如 STM32F1 的寄存器该怎么配、HAL 库怎么用、MISRA 规则检查。这些东西如果有对应的 skill，我就能更准确地帮你写代码。

## 简单判断要不要 skill

问自己一个问题：

> "这件事我没给 Claude 任何额外资料，它能做好吗？"

- **能** → 不需要 skill
- **不能**（需要特定知识/流程/规范）→ 需要 skill

比如"帮我写 STM32 的 GPIO 初始化代码"——你有 stm32-mcp 能编译烧录，但写代码本身不需要 skill，因为 HAL 库的 GPIO 配置是通用知识。但如果你要"所有代码必须符合 MISRA-C 2012"，那就需要一个 MISRA skill。
