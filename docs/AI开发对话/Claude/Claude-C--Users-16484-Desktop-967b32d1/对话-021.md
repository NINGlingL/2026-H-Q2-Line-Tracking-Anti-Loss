## 根本差异

| | STM32F103 | MSPM0 G3507 |
|------|------|------|
| 内核 | Cortex-M3 | Cortex-M0+ |
| 主频 | 72 MHz | 80 MHz |
| 开发库 | ST HAL / LL | TI DriverLib |
| 配置工具 | CubeMX | SysConfig |
| 寄存器 | ST 定义 | TI 定义，完全不同的地址和位段 |

外设 API 完全不同——举个例子，同样是初始化 GPIO：

```c
// STM32F103 — ST HAL
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);

// MSPM0 G3507 — TI DriverLib
DL_GPIO_setPins(GPIOA, DL_GPIO_PIN_5);
```

**没有一行外设代码能直接移植。** 函数名、参数、结构体全都不一样。

---

## 能复用的部分

| 可复用 | 不能复用 |
|--------|---------|
| 纯算法逻辑（PID、滤波、状态机） | 所有外设驱动（GPIO/UART/SPI/TIM/ADC/...） |
| 通信协议处理 | 中断服务函数 |
| 数据结构定义 | 时钟配置 |
| 业务逻辑层 | DMA/NVIC 配置 |
| | `.ioc` 工程文件 |

---

## 工作量估算

假设你的 F103 项目有 1000 行代码：

- 纯逻辑层（300 行）→ **基本不用改**
- 外设驱动层（700 行）→ **全部重写**
- 加上 SysConfig 重新配引脚、时钟、DMA

实际工作量大概是**原项目的 60-80%**，不是复制粘贴，是对着 F103 的逻辑重写一遍 G3507 的实现。

---

## 什么时候值得做

- 项目逻辑复杂（几千行算法）→ 值得移植
- 项目以 GPIO 控制为主 → 改起来快，值得
- 项目外设密集（多路 UART + SPI + Timer + ADC）→ 工程量大，不太值
