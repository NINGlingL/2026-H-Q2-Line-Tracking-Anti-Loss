## 二、MCP 调用的工具链，对安装位置有要求吗？

**取决于具体 MCP Server 的代码实现**。分三种情况：

| 方式 | 怎么找到工具 | 举例 |
|------|-------------|------|
| **PATH 查找** | 直接在系统 PATH 里搜命令名 | `subprocess.run(["STM32CubeIDE", ...])` → 只要 CubeIDE 在 PATH 里就行，装哪无所谓 |
| **环境变量** | 从环境变量读安装路径 | `os.getenv("CUBE_IDE_HOME")` → 需要你设好环境变量指向安装目录 |
| **硬编码路径** | 写死了安装位置 | `"C:/ST/STM32CubeIDE/..."` → 必须装在它指定的位置，否则跑不起来 |

大多数写得好 MCP Server 用的是 **PATH 查找**，位置不限。但具体到每个项目，需要看它源码才知道。比如 `shieldyguy/stm32-mcp` 的 README 里写的前提条件是：

> Prerequisites: STM32CubeIDE, Python 3.10+, OpenOCD, stlink tools

它没写死路径，说明应该是走 PATH 查找。**你可以先装好工具（任意位置，确保命令行能调用），如果报找不到再配**。

## 三、能不能自己改 MCP 的工具描述和行为？

这里需要区分两层：

### MCP 的工具描述是怎么来的

MCP Server 启动时，会向 Claude Code 注册一个工具列表，包含工具名、参数说明。**这写死在 Server 的源代码里**，不是配置文件。所以不能"改个描述"就生效。

### 只改描述没有意义

假设一个 MCP Server 注册了：

```python
# Server 源码中
@server.tool()
async def build_firmware():
    """使用 Keil 编译项目"""    # ← 这行是描述，只给 AI 看
    subprocess.run(["UV4.exe", "-b", "project.uvprojx"])  # ← 这行才是实际干的活
```

你只把描述改成"使用 CubeIDE 编译"，实际执行还是调 Keil。**AI 会被骗过去，但代码跑不起来。**

### 真正需要改的是执行逻辑

如果你想把它从 Keil 改成 CubeIDE，**需要改 MCP Server 的源代码**，把命令从：

```python
subprocess.run(["UV4.exe", "-b", "project.uvprojx"])
```

改成：

```python
subprocess.run(["STM32CubeIDE", "--headless", "--build", "project"])
```

同时别忘了上游依赖——Keil 编译用的是 `.uvprojx` 工程文件，CubeIDE 用的是 `.cproject`，改了编译命令还得保证工程文件格式匹配。

### 实际操作上

MCP Server 安装后一般在以下位置之一：

- `pip install` 装的 → Python site-packages 里
- `npm install` 装的 → `node_modules` 里
- 手动 git clone 的 → 你放哪就在哪

**找到它的源码直接改就行**，改完重启 MCP Server 生效。

## CubeMX + CubeIDE 的工作流，`shieldyguy/stm32-mcp` 是否兼容？

**基本兼容，但有一个重要区别要注意。**

---

### 你的工作流

```
CubeMX → 配置引脚/时钟/外设 → 生成代码(.ioc + .cproject + 源码)
  ↓
CubeIDE → 写应用逻辑 → 编译 → 烧录 → 调试
```

### shieldyguy/stm32-mcp 的工作流

```
Claude Code → 改源代码 → 调 MCP 编译 → CubeIDE headless 编译 → 调 MCP 烧录 → ST-Link 烧录
```

---

### 兼容的部分

CubeMX 生成的代码，选 CubeIDE 作为 IDE 时，生成的是一个完整的 **CubeIDE 工程**，包含：
- `.cproject` / `.project` — Eclipse/CDT 工程文件（CubeIDE 的编译系统）
- `.ioc` — CubeMX 配置文件
- 生成的 HAL 代码 + 用户代码区（`USER CODE BEGIN/END` 注释块）

CubeIDE 的 headless 编译只需要 `.cproject`，**不依赖 CubeMX**。所以：

| 操作 | 是否支持 |
|------|----------|
| 修改 `main.c` 中的应用逻辑 | ✅ 完全支持 |
| 修改其他用户代码 | ✅ 完全支持 |
| 编译项目 | ✅ CubeIDE headless 直接编译 |
| 烧录固件 | ✅ OpenOCD + ST-Link |

### 不兼容的部分

| 操作 | 是否支持 | 说明 |
|------|----------|------|
| 修改 `.ioc` 配置（改引脚、改时钟、加外设） | ❌ **不支持** | MCP 不会调 CubeMX 生成代码 |

这就是关键限制：**如果你只是写应用逻辑，够用；如果你要改硬件配置，MCP 管不了。**
