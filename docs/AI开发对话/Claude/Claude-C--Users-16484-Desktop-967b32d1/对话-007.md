### 具体场景对比

**场景 A（MCP 能搞定）：**
> 你在 CubeMX 里配好了 USART2 PA2/PA3，生成了代码。现在想写一个串口回显程序 → Claude Code+MCP 直接帮你写代码、编译、烧录，全程自动。

**场景 B（MCP 搞不定）：**
> 你想把 USART2 从 PA2/PA3 改到 PB6/PB7，并且加一个 DMA 通道 → 需要你先在 CubeMX 里改 `.ioc`，手动重新生成代码，之后 MCP 才能继续工作。

---

### 总结

`shieldyguy/stm32-mcp` 的 README 说"只需要 CubeIDE"，没说错——它管的是**编译和烧录**，不需要 CubeMX。你的 CubeMX+IDE 工作流里，它覆盖的是**IDE 那后半段**，CubeMX 那前半段（硬件配置）仍然需要你手动操作。

要不要先装上试试？毕竟日常开发 80% 的时间都在改应用代码，MCP 能省掉不少重复操作。

顺便说一句，之前搜到的安装信息已经足够我先给你介绍用法。它**不是 PyPI 包**，安装方式是这样：

```bash
# 1. 克隆仓库
git clone https://github.com/shieldyguy/stm32-mcp.git
cd stm32-mcp

# 2. 创建虚拟环境 + 安装
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -e .

# 3. 注册到 Claude Code
claude mcp add stm32 -- .venv\Scripts\python.exe -m stm32_mcp.server
```

前提条件：
- STM32CubeIDE（位置不限，能在命令行调用就行）
- Python 3.10+
- OpenOCD
- ST-Link 调试器接上

---

装好之后，Claude Code 中可用的工具就是这些：

| 工具 | 功能 |
|------|------|
| `stm32_build` | 编译项目 |
| `stm32_flash` | 烧录固件 |
| `stm32_build_and_flash` | 一键编译+烧录 |
| `stm32_board_info` | 读取芯片型号、Flash 大小、电压 |
| `stm32_list_probes` | 列出连接的 ST-Link |
| `stm32_read_memory` | 读指定地址/变量值 |
| `stm32_write_memory` | 写内存 |
| `live_memory_start/read/stop` | 持续监控内存（最小 250ms 间隔） |
| `serial_list_ports` | 列出可用串口 |
| `serial_connect` | 连接串口 |
| `serial_send` | 发送数据 |
| `serial_read` | 读取数据 |
| `serial_sequence` | 多步串口测试（可插入延时） |

---
