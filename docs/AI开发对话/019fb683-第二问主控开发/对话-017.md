## 275. 助手

可行，但更适合“判断已经跑完一圈”，不适合单独承担“2cm 精准停车”。

当前陀螺仪确实已启用：

- `yaw_rate_dps` 正在辅助弯道差速 PID。
- OLED 显示的 YAW 是陀螺仪积分结果。
- 当前 YAW 被限制在 `-180°～+180°`，跑半圈时会发生跳变，跑完整圈后会重新接近 `0°`。
- 目前按下 PB21 时没有重新把 YAW 清零，只是沿用上电校准后的角度。

主要问题是，半径为 0.5m 时：

- 1°角度误差约等于 0.87cm 的位置误差。
- 要满足停车误差不超过2cm，YAW 总误差必须小于约2.3°。
- 纯陀螺仪积分受零偏、振动和温度影响，一圈下来偏差几度很正常，因此直接判断 `YAW≈0` 很可能提前或延后数厘米。
- 刚启动时 YAW 本来也是0°，必须增加“已经转过半圈”的条件，否则会误停车。

我更推荐这样的融合方式：

1. 按下 PB21 时记录当前方向为起点0°。
2. 使用不限制在±180°的累计转角，记录车辆确实已经转过约330°。
3. 接近350°时进入终点准备区，可以略微减速。
4. 六路终点线出现时立即使用刚加入的主动短刹——这是精确停车条件。
5. 如果循迹模块漏掉终点线，累计转角达到约365°～370°时由陀螺仪强制停车，作为保底。

也就是说，推荐优先级是：

`陀螺仪确认接近一圈 → 六路横线精确定位 → 主动短刹`

而不是：

`YAW回到0°直接停车 → 六路横线保底`

这样既利用了陀螺仪，又保留循迹模块在位置判断上的优势，理论上更容易稳定压到2cm以内。本轮只讨论，没有修改代码或提交 Git。
