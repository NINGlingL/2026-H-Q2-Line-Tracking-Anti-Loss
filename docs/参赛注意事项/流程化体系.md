# 参赛流程与检查体系

## 一、从材料清单到开题

- 材料清单公布前：训练焊接、串口、传感器、PID、版本管理等通用能力，不锁定最终机构。
- 材料清单公布后：采购清单内标准模块并逐个验证，建立可替换件表。
- 题目发布后：先做需求分解、整机结构草图、接口与资源表，再决定最终采购和加工。
- 强机械题必须尽快确认 CAD 与 3D 打印资源；若完全没有机械支撑，应把机械风险纳入选题判断。

## 二、模块交付标准

每个模块必须交付四样东西：接线表、最小测试程序、原始数据样例、通过标准。只看到“现象正常”不算完成。

例如八路寻迹模块需要保存：供电电压、八路原始值、黑白区域阈值、不同电池电量下的波动、串口帧格式和刷新率。

## 三、PCB 与焊接流程

1. 空板检查短路和焊盘方向。
2. 先焊电源链路，限流上电并检查各级电压。
3. 再焊主控与通信接口，逐区验证。
4. 最后接电机和其他大负载。
5. 每块板设置止损时间；超过时间仍不稳定，就切换成熟模块或洞洞板。
6. 所有最终接线做拉力检查、标记和固定，避免杜邦线把接触问题伪装成软件问题。

## 四、整车故障定位顺序

1. **供电**：电池静态电压、带载电压、稳压输出、共地、电流能力。
2. **连接**：插头方向、接触、焊点、线序、机械拉扯。
3. **传感器原始数据**：先观察八路值、IMU 值、编码器计数，不看融合后的最终状态。
4. **驱动层**：单独验证 PWM、方向、串口帧和定时器。
5. **控制层**：最后检查 PID、状态机、阈值和保护逻辑。

没有完成前一层的证据，就不要通过修改后一层代码“试试看”。

## 五、供电专项检查

- 每轮长时间调试前记录电池电压。
- 在电机、视觉和传感器同时工作时测量带载电压。
- OLED 或串口显示供电状态和关键模块原始数据。
- 保留已充满的测试电池与正式测评电池，并做好轮换标记。
- 传感器异常时先接稳压电源复测，快速区分供电和算法问题。

## 六、AI 与版本管理

- 固定项目事实文档：题目约束、引脚表、资源表、串口协议和已验证结论。
- 一个阶段尽量由同一模型持续协作；换模型时从事实文档和代码重新审阅。
- AI 给出的驱动或控制代码必须通过最小测试，不能直接进入整车。
- 每个可运行节点提交 Git；实验性参数和结构使用独立分支。
- 出现退化时先比较最后一个通过版本，不在未知状态上继续堆补丁。

## 七、比赛内建议里程碑

- 第一天：完成选题、系统架构、机械方案、接口资源表和关键风险验证。
- 第二天：机械与电路形成可集成版本，各模块有独立测试记录。
- 第三天上午：整车首次闭环；下午冻结基础得分版本；晚上挑战提高项。
- 第四天：只处理有证据的问题，保留正式测评稳定版本，不做高风险架构重写。
